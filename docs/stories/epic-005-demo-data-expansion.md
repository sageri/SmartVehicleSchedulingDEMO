## 🎯 Epic Goal

現在のDemoデータを **中規模実証環境** に拡張し、より現実的な物流シナリオ（2拠点・30配送先・5台車両）でのVRP最適化効果を実証できるようにする。

**最終実装仕様:**
- **拠点:** 2箇所（東京・さいたま市）
- **配送先:** 30件（東京20件 + さいたま市10件）
- **車両:** 5台（東京3台 + さいたま市2台）
- **拠点制約:** 各車両は所属拠点の配送先のみ配送可能
- **VRP最適化時間:** 60秒以内（従来の300秒から大幅短縮）

**スコープ変更履歴:**
- **2025-11-03 初期:** 4拠点・100件・10台から2拠点・40件・5台に調整（パフォーマンス改善）
- **2025-11-03 Story 5.1.1:** 拠点変更（横浜→さいたま市）、陸地制約追加
- **2025-11-04 最終:** 30件に最適化（東京20+さいたま10）、固定配送点採用、拠点-配送先関連付け実装

## 📋 Epic Description

**Integration Points:**
- `/api/v1/seed/demo-data` エンドポイント
- VRP最適化エンジン（OR-Tools CVRPTW）
- Frontend地図表示・結果分析UI

### Enhancement Details

**最終実装仕様：**

#### ① 集荷場所の拡張（拠点制約付き）

**拠点配置:**
```yaml
拠点1: 東京デポ
  位置: 35.6812, 139.7671（東京都千代田区丸の内）
  営業時間: 8:00-18:00
  配送エリア: 東京都内20箇所
  車両配分: 3台（2t車×2台、4t車×1台）

拠点2: さいたま市デポ
  位置: 35.8617, 139.6455（埼玉県さいたま市大宮区）
  営業時間: 8:00-18:00
  配送エリア: さいたま市周辺10箇所
  車両配分: 2台（2t車×2台）
```

**拠点制約（重要）:**
- 各車両は **所属拠点の配送先のみ** 配送可能
- OR-Tools の `SetAllowedVehiclesForIndex` で実装
- `Delivery.depot_id` フィールドで拠点関連付け

#### ② 配送先情報の拡張（固定配送点方式）

**配送点生成方式:**
- **従来:** ランダム生成（座標計算 + bearing制約）
- **現在:** **固定配送点リスト方式**（実在地点使用）

**配送点数:**
- **東京デポ周辺:** 20件（新宿区役所、渋谷駅、池袋など実在地点）
- **さいたま市デポ周辺:** 10件（さいたま新都心、浦和駅など実在地点）
- **合計:** 30件

**伝票枚数分布:**
```yaml
1枚: 50%（軽量・小型荷物）
2枚: 35%（標準荷物）
3枚: 15%（大型荷物）
```

**時間指定分布（VRP解探索性向上のため最適化）:**
```yaml
午前指定: 20%（8:00-13:00）- 午後と1時間重複
午後指定: 30%（12:00-18:00）- 午前と1時間重複
時間指定なし: 50%（8:00-18:00）- 柔軟性大幅向上
```

**重要改善点:**
- 時間窓に1時間の重複期間を設定し、空白期間を排除
- 待機時間許容を30分→60分に拡大
- 指定なしの比率を10%→50%に大幅増加（解探索性向上）

#### ③ 車両情報の拡張（Multi-Depot対応）

**車両配分:**
```yaml
東京デポ（拠点1）:
  2t車: 2台（vehicle-101, vehicle-102）
  4t車: 1台（vehicle-201）
  小計: 3台

さいたま市デポ（拠点2）:
  2t車: 2台（vehicle-103, vehicle-104）
  小計: 2台

合計: 2t車×4台、4t車×1台（計5台）
```

**車両スペック:**
```yaml
2t車:
  容量（重量）: 2000kg
  容量（容積）: 10.0m³
  コスト: 50円/km、2000円/時間

4t車:
  容量（重量）: 4000kg
  容量（容積）: 20.0m³
  コスト: 80円/km、3000円/時間
```

### How It Integrates

1. **データモデル拡張:**
   - `Delivery` モデルに `depot_id` フィールド追加（ForeignKey）
   - データベーススキーマ変更（マイグレーション不要、SQLiteは再作成）

2. **VRP最適化エンジンへの影響:**
   - **拠点制約追加:** `SetAllowedVehiclesForIndex` で実装
   - **Multi-Depot対応:** 各車両が所属拠点から出発・帰還
   - **計算時間最適化:** 300秒→60秒に大幅短縮（初期解戦略変更）
   - **解探索戦略変更:** PATH_CHEAPEST_ARC → PARALLEL_CHEAPEST_INSERTION

3. **Frontend表示への影響:**
   - 地図表示範囲の自動調整（2拠点+30配送先）
   - 拠点カラー変更（横浜→さいたま市）
   - HTTP タイムアウト: 360秒→120秒（Backend最適化に合わせて短縮）
