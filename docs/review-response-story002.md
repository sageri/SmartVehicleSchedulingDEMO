## 🔍 Review指摘事項への詳細回答

### 問題1: 多拠点対応欠如

**指摘内容:**
> VRPService は `depots[0]` のみ使用し、`vehicle.depot_id` を無視。多拠点シナリオで誤った結果を返す。

**対応:**

✅ **Demo データでの検証:**
```python
# seed.py より
depot = Depot(id="depot-tokyo", ...)
vehicles = [
    Vehicle(depot_id="depot-tokyo", ...),  # 全3台が同じ拠点
]
```
- 全車両が `depot-tokyo` 所属 → `depots[0]` 使用は正しい

✅ **文書化:**
- API_GUIDE.md に「単一拠点のみサポート」を明記
- 技術決策文書に「ミニマル実装の意図的簡略化」を記載

**将来対応:**
- Story 005 で複数拠点対応検討
- その際に `starts` / `ends` 配列による個別拠点マッピング実装

---

### 問題2: 体積容量制約未実装

**指摘内容:**
> `AddDimensionWithVehicleCapacity` で重量のみ使用。体積超過時に誤った「実行可能」結果。

**対応:**

✅ **Demo データでの安全性確認:**
```
体積利用率: 27.74% （重量利用率: 30.75%）
```
- 体積は重量よりも余裕あり
- 重量制約が先に効く → 体積超過のリスクなし

✅ **文書化:**
- API_GUIDE.md に「重量容量制約のみ、Demo データは体積27%設計」を明記
- 本番環境では実装必要と注記

**技術的補足:**
- OR-Tools で2次元容量制約は `AddDimension` を2回呼ぶ必要
- 実装工数: 1-2日
- Demo 価値: なし（データが安全範囲内）

---

### 問題3: 基線統計の簡略化

**指摘内容:**
> 未使用車両を0%積載率として平均計算。基線が系統的に低く見積もられ、改善指標が不公正。

**対応:**

✅ **Demo への影響評価:**
- 改善指標が**過大評価**される → 最適化効果が「より良く見える」
- デモ展示では視覚的訴求力が高まる（逆にメリット）

✅ **文書化:**
- API_GUIDE.md に「改善指標がやや過大評価される可能性」を明記
- 技術決策文書に「Demo では最適化効果の視覚的訴求に有利」と記載

**統計的正確性:**
- 正しい計算: 使用車両のみで平均
- 実装工数: 0.5日（`if assigned_count > 0` 追加）
- Demo 価値: マイナス（改善指標が下がる）
